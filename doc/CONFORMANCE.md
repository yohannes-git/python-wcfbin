# MC-NBFX, MC-NBFS and MC-NBFSE conformance matrix

Traceability of every requirement of [MC-NBFX] (sections 1.3 to 4), [MC-NBFS] (2 to 4) and [MC-NBFSE] (2 to 4) to the code of the `wcf` package and to the tests that prove it (revision 244e72c).

Each requirement has a stable identifier. "Test" names the existing tests of `tests/` (`module::method`, or `doctest:` and the documented object) and, after "trace:", the method of `tests/test_spec_traceability.py` named after the identifier, which checks it again by execution (the test of a non-conformant requirement fails). Implementation references are relative to `wcf/` (`base.py` and the other record modules are in `wcf/records/`).

Statuses: **Covered** (implemented and proved by a test of the other modules), **Covered by its traceability test** (proved by `tests/test_spec_traceability.py` only), **Non-conformant**, **Documented deviation** (README, "Where the text of the specification is not followed" and "Untrusted input"), **Out of scope**.

## Documented deviations

* **NBFX-2-UNCLOSED-ELEMENT**: Refused, as the .NET binary reader does ("unexpected end of file", checked on .NET Framework 4.8.1): a tree decoder needs closed elements, and it detects truncated documents.
* **NBFX-2.1.2-CANONICAL**: README: a non-minimal encoding is refused (.NET accepts it).
* **NBFX-2.1.3-NO-RESTRICTION**: Decoded and encoded as is; README: render_xml() refuses names that are not NCNames and comments XML cannot carry.
* **NBFX-2.2.3.9-10-EXPONENT-100**: README: the text is followed; .NET writes "100".
* **NBFX-2.2.3.11-TRAILING-ZEROS**: README (examples and .NET followed): written with its scale ("1.50"), the scale being part of the DECIMAL that "the least number of digits" must reproduce.
* **NBFX-2.2.3.12-VALUE-MAX-LOCAL**: README (examples and .NET followed): for TZ=2 the field is DateTime.ToBinary(), a time before 0001-01-01T00:00:00Z being folded below 2^62; a local time beyond year 9999 is refused.
* **NBFX-2.2.3.12-FORMAT-DATE-ONLY**: README: the time is always written (section 3 example "2006-05-17T00:00:00", .NET).
* **NBFX-2.2.3.12-TZ-LOCAL**: README (examples and .NET followed): the field holds the UTC ticks (DateTime.ToBinary()), rendered as the local time of the decoding host with its offset (DateTime.FromBinary()); the offset itself is the one the text requires.
* **NBFX-2.2.3.13-SURROGATE-PAIR**: Refused, as the .NET binary reader does (checked on .NET Framework 4.8.1: a pair of 3-byte surrogate sequences fails, the 4-byte UTF-8 form is read): UTF-8 is RFC 3629, where encoded surrogates are invalid.
* **NBFX-2.2.3.13.1-WHITESPACE-REFERENCES**: README: written as character references so that an XML parser keeps them.
* **NBFX-2.2.3.23-FORMAT**: README: xsd:duration, as the section 3 examples ("-PT5M44S", "PT3H20M") and .NET.
* **NBFX-2.2.3.29-LENGTH**: README: INT32, as the section 3 example ("BA 04 00 00 00 33 00 32 00") and .NET.
* **NBFX-2.3.2-RENDER**: README: a comment XML cannot carry ("--", final "-", CR, illegal characters) is refused by render_xml().
* **NBFS-3-EX-FROM-XML**: README ("Values are lexical text by default"): "1" and "0" become Chars8Text, not OneText and ZeroTextWithEndElement; a type map gives typed records. Every other record is the one of the example.

## Errata of the specification

Where an example of the specification contradicts its own rules, the rules are followed:

* **NBFX-2.1.2.4-EX**: Specification erratum: these 4 bytes are 2097152 (0x200000); 268435456 is 0x10000000, 5 bytes (range table, example of 2.1.2.5). The library follows the range table.
* **NBFX-2.2.3.10-EX**: Specification erratum: 0x4005BF0A8B145774 is 2.71828182845905 (section 3 DoubleText row, shortest form); "2.7182818284590451" is 0x4005BF0A8B145769 (e).
* **NBFX-2.2.3.11-EX**: Specification erratum: the number printed has Lo64 = 0x4F2D80 (5.188992); 5.123456 is 0x4E2D80, the bytes "80 2D 4E" of the section 3 DecimalText row.
* **NBFX-2.2.3.13-EX**: Specification erratum: 0x41 0x42 0x43 is "ABC".
* **NBFX-2.2.3.27-EX**: Specification erratum: these bytes are "ABC".
* **NBFX-3-EX-DoubleText**: Agrees with the shortest form; see NBFX-2.2.3.10-EX (erratum of 2.2.3.10).
* **NBFX-3-EX-PrefixAttributeK**: the published row has two spaces between the attributes.
* The minus sign of 2.2.3.5 to 2.2.3.8 is printed as an en dash ("–"); the examples use "-".
